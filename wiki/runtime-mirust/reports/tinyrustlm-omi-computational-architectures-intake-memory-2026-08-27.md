## Durable Decision

The reports do not justify a new production architecture. Their strongest
contribution is a common enterprise discipline for the current one:

1. one authoritative clean-slate contract and implementation per concern;
2. bounded typed operations with exact identity, parentage, capability,
   declared mutation scope, cancellation, and terminality;
3. natural-language content is data and never authorization or proof;
4. contradictions, uncertainty, negative results, and immutable failures stay
   explicit;
5. replay binds software, artifacts, seeds, ordering, numeric profile, and
   resource limits;
6. observability and evidence are private by default and publicly minimized;
7. advanced research competes against a simpler baseline under equal resource
   and quality accounting;
8. no hidden retries, repair, fallback, self-modification, compatibility, or
   deferred cleanup.

TinyRustLM remains one prelaunch product with one SLM2 six-member composition,
one Rust semantic runtime, differential native/WASM proof, one dedicated
browser worker event path, local UAIX memory, authorized MemoryEndpoints
portable continuity, and direct P2P-or-local-conversion acquisition.

## Domain Decisions

### Authority And State

Adopt typed epistemic status, exact operation graphs, capability checks, and
declared mutation sets. Execute state changes against an isolated candidate and
reject an observed diff outside the declaration. Do not create a monolithic
OMI kernel or language-spanning framework to express these invariants.

### Memory

Keep immutable weights, adapters, ephemeral KV, transcript, local UAIX,
retrieval state, and MemoryEndpoints records separate. Preserve provenance,
contradictions, supersession, tombstones, and current-turn precedence.
Retrieved text remains untrusted. Runtime use must never update weights or
silently consolidate durable memory.

### Evidence And Observability

Distinguish process provenance from support provenance. Preserve typed parent,
input, output, resource, cancellation, and terminal records. Exact private
evidence supports debugging; public records expose only bounded safe facts.
Raw prompts, portable-memory payloads, credentials, unsafe paths, and guessable
secret digests are prohibited. No centralized telemetry or graph database is
needed for correctness.

### Dialogue, Planning, And Tools

Use bounded information-seeking for true ambiguity, explicit consent before
new data sources, whole-plan feasibility checks, and declared deterministic
tools. A tool contract may later define preconditions, effects, capabilities,
duration, cancellation, and compensation. Model prose and memory prose never
authorize a tool. No hidden algorithmic or runtime fallback is allowed.

### Research

Equality saturation, energy models, sequence-memory experiments, topological
or sheaf validation, world models, and hierarchical skills remain optional
shadow research. Each needs a narrow bottleneck, preregistration, simple
baseline, negative controls, immutable inputs, equal compute/memory/latency
accounting, and an explicit reject decision. Physical control, sensors,
robotics, and digital twins are outside the current product.

## Explicit Rejections

- generic cognitive IR/compiler and many-dialect runtime;
- monolithic OMI kernel or five-language semantic clones;
- gRPC, REST, ZeroMQ, Neo4j, or new microservice topology for this intake;
- runtime e-graphs, energy search, probabilistic programs, or artifact scripts;
- test-time learning, fast-weight exchange, self-training, or silent memory
  consolidation;
- GGUF, llama.cpp, remote inference, provider fallback, relay fallback, or
  federated model mutation;
- privacy, determinism, infinite-context, benchmark, or production claims
  without local evidence;
- compatibility readers, migrations, aliases, dual paths, and postponed
  deletion.
