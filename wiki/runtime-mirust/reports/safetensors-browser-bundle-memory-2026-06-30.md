## Implementation

`tinyrustlm-slm-pack browser-safetensors-trained-bundle <output-tinyrustlm-root> <input.safetensors> <source-shape> <output-source-dir> [f32|q8_0|q4_0|all] [eval-cases.txt|candidate.review] [candidate-review]` now bridges local safetensors checkpoints into a runnable TinyRustLM root.

The command validates the browser bundle quantization selector before writing output, optionally verifies that the supplied candidate review still matches the safetensors source plan, requires the requested bundle quantization to match `browser_admission_preferred_quantization` or use `all`, resolves the review's local `eval_cases_route` when a candidate review is supplied without an explicit eval file, rejects explicit eval-file drift against that reviewed route before extraction, revalidates local license, reference-prompt, and eval-case artifact rows when file-backed, extracts the safetensors payload into the reviewed raw f32 trained-source layout, validates that preserved source directory, then reuses `browser-converted-trained-bundle` internals to stage `models/selector.registry`, converted `.slm` files, `.slm.manifest` files, source-validation/runtime/eval/admission evidence with `source_validation_path`, `runtime_smoke_path`, `eval_path`, `admission_path`, and the reviewed `eval_cases_route` appended into each eval sidecar, per-entry `converted-trained.source.manifest` snapshots, per-entry `converted-trained.source.review` snapshots, runtime WASM manifest, and the app shell.

Candidate reviews now bind `browser_admission_preference_order=q8_0,q4_0,f32`; f32-over-budget reviews prefer q8_0 when it fits and fall back to q4_0 only when q8_0 also exceeds the selector budget.

When a candidate review is supplied, the preserved raw `source.manifest` records `source_review_kind`, `source_review_status`, `source_review_checksum`, and `source_review_required_next_gate`. The converted-trained browser bundle copies those fields plus `source_review_path=../evidence/<candidate-id>/converted-trained.source.review`, writes `converted-trained.source.validation`, and carries `source_validation_path=../evidence/<candidate-id>/converted-trained.source.validation`, `runtime_smoke_path=../evidence/<candidate-id>/converted-trained.runtime`, `eval_path=../evidence/<candidate-id>/converted-trained.eval`, and `admission_path=../evidence/<candidate-id>/converted-trained.admission` into admission and selector registry evidence. The browser verifies them against the fetched source manifest, fetched candidate-review sidecar, fetched source-validation sidecar, fetched runtime-smoke sidecar, fetched eval sidecar, and fetched admission sidecar before requesting the selected `.slm`. The fetched review sidecar must carry reviewed source model id, SHA-shaped source revision, config/tokenizer checksums, tokenizer import status/count/checksum rows, license route, reference prompt route, reference output checksum, and eval-cases route; if it carries local config/tokenizer artifact rows the browser requires their checksums to match the reviewed config/tokenizer checksums; Model Provenance renders Source Review, Review Routes, Review Artifacts, Tokenizer Import, Source Validation, and Admission rows from checksum-verified sidecars; the fetched source-validation sidecar must carry `validate-source`, pass status, source manifest checksum, source identity, tensor count, tied-output flag, optional source-review checksum, and next conversion gate; the fetched runtime sidecar must carry the runtime-smoke gate and pass decision; the fetched eval sidecar must echo that eval-cases route; and the fetched admission sidecar must echo candidate artifact path, bytes, `.slm` checksum, tokenizer checksum, source/review/validation/runtime/eval paths and checksums, promotion decision, selector status, public claim status, and `required_next_gate=browser-selector-loads-only-admission-record-artifacts` before model bytes.

The bridge accepts TinyRustLM local tensor names and Hugging Face Llama aliases through the same safetensors source planner used by `convert-safetensors-trained`. The preserved `output-source-dir` remains the durable source evidence between checkpoint bytes and browser-loaded modules.

The reviewed BPE fixture pipeline uses `tiny-fixture-bpe`, local config/tokenizer JSON artifacts, an explicit eval-cases file, and output selector mode `all`. It validates the inspection report, source-plan report, candidate-review rows, review checksum in the raw `source.manifest`, direct q8_0 `.slm` conversion with `BPE1`, all three browser-admitted `.slm` files (`f32`, `q8_0`, `q4_0`), each copied source-review sidecar checksum, each `converted-trained.source.validation` route/checksum, each `converted-trained.runtime` route/checksum, each `converted-trained.eval` sidecar, and the generated `models/selector.registry` against the three admission records.
