## Exact Root Cause

The process terminal has a closed executable identity shape of
`byteLength` plus `sha256`. The owner contract's registered Python executable
identity also carries the basename. The verifier compared these entire objects
instead of deriving and comparing the normative process-terminal projection.

Observed registered Python identity:

```text
basename = python.exe
byteLength = 104952
sha256 = 4d6f5f81a4bca11191c4c7c6b43632694d0a4ce74e068619d8fdc161d469859a
```

Observed process-terminal before and after identity:

```text
byteLength = 104952
sha256 = 4d6f5f81a4bca11191c4c7c6b43632694d0a4ce74e068619d8fdc161d469859a
```

The meaningful executable identity fields match. The verifier rejected because
whole-object equality also required the absent basename field. This is a
general source-owned verifier defect. It does not make the current operation a
pass and does not authorize a permissive second shape.
