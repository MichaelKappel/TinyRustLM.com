## Root-Cause Chain

The diagnosis occurred only under new bounded diagnostic identities, outside
the closed operation.

1. Importing the pinned Transformers closure imports urllib3. Its IPv6
   capability test attempts one local `socket.bind` using AF_INET6,
   SOCK_STREAM, protocol 0, address `::1`, and ephemeral port 0. The former
   policy denied every bind. A broad model-load exception boundary then
   converted the typed isolation rejection to `source-trace-model-load`.
2. The clean-slate isolation policy now permits exactly one such event only
   when the caller is `urllib3.util.connection._has_ipv6`. It still denies a
   second bind; another family, type, protocol, address, port, module, or
   function; and every connect, DNS, listen, send, subprocess, or remote-code
   route. `trust_remote_code=False` is explicit. Typed `SourceOwnerFailure`
   values are rethrown rather than masked.
3. After the exact capability event was admitted, a fresh diagnostic reached
   `Qwen3ForCausalLM.from_pretrained` and exposed a `NameError` in
   `transformers.modeling_utils.get_init_context`. Transformers 4.51.0 requires
   Accelerate for the low-memory model-load path, but the former environment
   closure omitted it. The sole current environment now binds Accelerate
   1.14.0 and psutil 7.2.2 along with the already pinned packages.
4. Code review then found a separate future-execution defect: the owner
   observed seven package identities but compared them with a five-package
   request map, while the independent verifier admitted only five. A red test
   froze one coherent source request/producer/verifier contract. The sole
   current request schema is
   `tinyrustlm.qwen3_numerical_source_request.v2`; the source implementation is
   `tinyrustlm.qwen3-publisher-source-trace/2`; both request and verifier bind
   Accelerate and psutil. The shipping path has no `/1` acceptance branch.

Historical `/1` records remain data. They do not authorize executable
compatibility.
