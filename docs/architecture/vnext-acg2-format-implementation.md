# ACG2 Exact Champion Composition Implementation Checkpoint

## Status

ACG2 is implemented as an unpromoted technical format, bounded resolution,
and fail-atomic activation boundary for TinyRustLM's one prelaunch product.
The implementation consists of one closed machine profile, a built-ins-only
Node oracle, generated cross-language vectors, an unsafe-free Rust crate, an
import-free WASM conformance ABI, and focused native and fresh-browser tests.

This checkpoint is not a product release and does not create a product V2.
`ACG2`, its technical version 2.0, the corrected preregistration schema suffix
`v2`, and repository paths containing `vnext` are exact protocol or repository
identities only. There is no released population, compatibility cohort,
migration obligation, old-product fallback, or authority to retain superseded
executable code.

No real source model has been converted through this graph. Product runtime
integration, browser-local generation, quality qualification, P2P admission,
package release, site deployment, and publication remain open.

## Closed Binary Profile

The sole format identifier is `org.minimodel.acg2/2.0`, and the sole initial
composition profile is `tinyrustlm.champion-composition-five-member/1`.
One graph is exactly 896 little-endian bytes:

- one 256-byte header;
- exactly five 128-byte member records;
- no member payload bytes;
- no padding between records;
- no trailing data.

The header binds magic `ACG2`, CRLF, SUB, LF; fixed padded format ID;
technical version 2.0; little-endian byte order; champion-chat artifact
class; zero flags; exact file and table geometry; checked resolved-member
length; graph identity; member-table digest; and zero reserved bytes.

The records are exactly model, tokenizer, template, sampling, and prompt.
Each record binds record version, closed role, closed format, zero flags,
zero-based ordinal, positive role-bounded byte length, exact artifact SHA-256,
exact format-profile SHA-256, and zero reserved bytes.

Role owns ordinal, format code, profile hash, and maximum artifact length.
The Rust public constructor therefore accepts only role, artifact length, and
artifact digest. Callers cannot supply a conflicting format or profile and
ask the writer to serialize it.

The profile has 22 stable error codes. Unknown versions, classes, enums,
flags, profiles, dimensions, padding, paths, locators, optional members,
extensions, or surplus bytes do not enter an ignored-field path.

## Identity Derivation

The member-table digest is plain SHA-256 over the complete 640 record bytes.

The graph identity is SHA-256 over:

1. ASCII `tinyrustlm.acg2.champion-graph.v1`;
2. one zero byte;
3. exact little-endian version fields;
4. artifact class;
5. member count;
6. resolved-member byte total; and
7. all 640 member-table bytes.

The whole artifact identity is plain SHA-256 over the complete 896 graph
bytes. Table, graph, and artifact identities are separate typed facts.

Every arithmetic operation used to derive ranges or resolved totals is
checked. The exact aggregate member ceiling is 68,787,700,488 bytes. The
parser rejects all 896 proper prefixes and every surplus byte before it can
be treated as a graph.

## Independent Node Oracle

`tinyrustlm/tools/acg2-reference.js` uses Node built-ins only. It does not
import Rust output, invoke a subprocess, use the network, or read a generated
Rust artifact. It independently implements profile verification, graph
writing, graph parsing, all three identities, canonical and alternate fixture
construction, and hostile-vector generation.

The command supports three explicit modes:

- `--check` regenerates in memory and requires byte equality with the
  checked-in vector file;
- `--write-create-only` creates the vector file only when absent; and
- `--write` is an explicit development rewrite used before the implementation
  checkpoint is frozen.

Normal verification uses `--check`. No test repairs generated output, selects
an easier vector, or updates evidence as a side effect.

The vector corpus contains the canonical graph, one distinct valid-model
graph, all 896 proper-prefix expectations, and 32 named hostile artifacts.
Hostile cases cover header identity and layout, all reserved ranges, table and
graph digests, each member role/format/order/profile/length/identity boundary,
all-zero identities, overflow-relevant geometry, and trailing data.

## Rust Format Owner

`rust/crates/tinyrustlm-composition2` is a standalone exact-lock Rust 2021
workspace. It denies unsafe code and missing public documentation. The root
workspace and root lockfile remain byte-identical to their registered evidence
state until the complete product-consumer replacement is ready.

The isolation is an implementation staging boundary, not a second supported
runtime. There will be one registered production owner after the clean cut.

`write_acg2` constructs all 896 bytes in one bounded local buffer, derives
the table and graph digests, writes the complete buffer, and returns no success
identity if output fails. Durable callers must still use an owned create-only
same-directory staging file, flush and sync it, independently parse and hash
it, then atomically promote it. The format writer does not turn a partial
filesystem write into a receipt.

`Acg2Graph::from_bytes` validates the exact profile before exposing typed
members. `Acg2Policy` can only narrow the profile-wide graph byte ceiling; it
cannot expand member counts, formats, or role limits.

## Bounded Resolution

`MemberResolver` receives a closed `MemberRole` and complete immutable member
identity. It returns one owned `Read + Seek` source. The graph contains no
path, URL, alias, catalog name, or mutable store key.

Resolution proceeds in exact member order:

1. verify that every compiled canonical owner profile equals ACG2's profile;
2. open exactly one member source;
3. seek to determine the exact observed byte length;
4. stream SHA-256 through one fixed 1 MiB buffer;
5. require exact length and artifact digest;
6. rewind and invoke the canonical member owner;
7. drop that source before opening the next member;
8. validate Prompt2-to-graph dependency closure;
9. create the complete resource plan; and
10. require resource preflight acceptance before returning a candidate.

The model is validated directly from the member source through
`tinyrustlm-slm2::validate_model`. The resolver does not retain model artifact
bytes and does not create an F32 weight shadow. Tokenizer2, Template2,
Sampling2, and Prompt2 are bounded by their much smaller exact profile limits
and are composed through `Prompt2Runtime::from_artifacts`.

Only one source is open at a time. The candidate retains validated model
metadata and the dependency-closed Prompt2 runtime, not a second model-byte
copy. Product scalar execution and long-lived model-source ownership remain a
consumer-integration gate.

## Dependency Closure

Five individually valid artifacts are insufficient. Before resource preflight,
the implementation requires:

- the model profile to equal the mixed-Q8 SLM2 profile;
- the tokenizer profile and artifact to equal the accepted Tokenizer2 owner;
- the template profile and artifact to equal the accepted Template2 owner;
- the sampling profile and artifact to equal the accepted Sampling2 owner;
- the prompt profile and artifact to equal the corrected Prompt2 owner; and
- Prompt2's embedded model and dependency identities to close over that same
  selected graph.

The superseded dense-F32 Prompt2 dependency and the first ACG2 registration do
not enter an alias or translation table. They fail before activation.

## Resource Preflight

The complete immutable `ResourcePlan` exposes graph identity, resolved-member
bytes, model artifact bytes, retained non-model dependency bytes, validated
model tensor count, and the fixed stream-buffer size. The caller accepts or
rejects that complete plan once.

Preflight rejection returns `acg2-resource-preflight` before candidate state
can reach the activation owner. The implementation does not begin activation
and then attempt to recover from allocation pressure.

## Transactional Activation

`PreparedComposition` can be produced by the production path only after graph
validation, exact member hashing, canonical parsing, dependency closure, and
resource preflight all succeed.

`ActivationState` is the sole activation owner. It holds one optional active
composition, committed KV byte count, bounded generated-token state, exact
operation identity, and visible transcript revision.

Activation has one fallible check: the caller's expected operation identity
must equal the current operation identity. A stale identity returns
`acg2-stale-operation` before mutation and preserves active graph, KV,
generation, operation, and transcript state.

After that check, activation is one ownership swap. It installs the prepared
candidate, clears incompatible KV and generation state, advances operation
identity to the new graph identity, and preserves the visible transcript.
There is no partial member activation, rollback parser, retry selector, or
best-effort cache reuse.

## Browser Conformance Boundary

The Rust crate exports one raw conformance ABI only on `wasm32`. It has no
WASM imports, no unsafe block or declaration, and no network authority. The
ABI exposes bounded input/output/error buffers plus exact generate, parse,
profile, and clear operations.

The WASM boundary exists to prove that the same Rust writer and parser execute
under WebAssembly. It is not a product worker, model loader, tokenizer owner,
generation runtime, or release artifact.

The browser test launches a fresh Chromium profile, serves only an owned local
test page, asserts zero unexpected network requests, and replays canonical and
all 32 hostile vectors. Node WebAssembly independently replays the same corpus.

## Preserved Development Failures

The first warnings-denied Clippy pass found one unused import and a large
test-only enum. Both were fixed in the uncommitted implementation before this
checkpoint; no lint was disabled and no size threshold was weakened.

The first preregistration-reconciliation test compared machine field names
directly even though the preregistration uses documentation-shaped names and
the implementation profile uses wire-shaped names. The test now normalizes
only those field labels and representation terms while still requiring exact
offsets, widths, order, dimensions, member identities, limits, and forbidden
behavior. The profile was not weakened to satisfy the test.

## Clean-Cut Obligations

The implementation checkpoint deliberately does not make ACG2 active while
old executable consumers remain. The next major replacement must update the
converter, native runtime, browser worker and model store, .NET and C ABI
surfaces, companion, P2P admission, release registry, and product UI around
one exact ACG2/SLM2 composition.

Once that complete consumer closure builds and passes, the same major change
must delete superseded executable ACG1 and SLM1 readers, writers, fixtures,
routes, aliases, model-selection branches, and support documentation. No
dual-runtime interval is a supported state. Historical content-addressed
receipts may remain inert audit truth only.

The codebase may be rewritten freely because the product is not public.
Keeping a superseded path for hypothetical users, old files, migration, or
rollback convenience is prohibited debt.

## Claim Boundary

This checkpoint proves a deterministic ACG2 profile, independent format
implementations, stable hostile rejection, bounded local member resolution,
dependency closure, preflight-before-mutation, fail-atomic in-memory
activation, and parser/writer execution in fresh Chromium.

It does not prove real model conversion, model correctness, model quality,
