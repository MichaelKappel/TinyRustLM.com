# Qwen3 SLM2 Converter Preregistration

Date: 2026-08-24

## Decision

The sole model-conversion path for TinyRustLM's one prelaunch product will be
`tinyrustlm-convert` reading an exact locked dense Qwen3 checkpoint and writing
the exact SLM2 mixed-Q8 profile. This is a clean replacement, not another
product generation. SLM2 and the numbered profile names are byte-contract
identities.

The machine contract is
`contracts/vnext/qwen3-safetensors-conversion-profile.v1.json`. It was written
before converter code changed and before any Qwen3 SLM2 output was created.
It is exactly 14,419 bytes at SHA-256
`313069152daa70a2c2b5070f9d1350379a5800f647d5c3ac8d23a75ff9ead968`.
Its registration parent is commit
`7334aab34107ce7d9ea3d0491856feb4166222d5`, tree
`9e81843bcfae256acbc0ffdffc1e2946319e2d66`.

## Source Boundary

One source lock binds exactly nine regular files: license, model card, model
configuration, generation configuration, merges, one Safetensors model,
tokenizer JSON, tokenizer configuration, and vocabulary. The source directory
may contain nothing else. Missing files, extra files, links, reparse points,
non-regular files, size drift, and hash drift fail before output creation.

The converter hashes every file with a fixed 1 MiB buffer before conversion
and repeats those identities before promotion. The SLM2 writer separately
reads every source tensor twice so derived payload hashing and final copying
cannot silently observe different bytes.

The lock admits an upstream checkpoint or a newly merged trained checkpoint.
That does not make either one useful. It only identifies the exact bytes being
converted. Product admission remains a later quality and provenance decision.

## Architecture Boundary

The converter accepts only the dense `Qwen3ForCausalLM` operator family with:

- SiLU-gated feed-forward blocks;
- causal grouped-query attention;
- no Q, K, or V projection biases;
- paired per-head Q and K RMSNorm vectors;
- RoPE without scaling;
- no sliding-window execution;
- tied token embeddings and output projection;
- BF16 or F32 source tensors with one dtype for the complete checkpoint.

The exact locked configuration determines dimensions. Shapes are then checked
against the closed SLM2 tensor registry. This exercises the same production
logic with tiny deterministic Qwen3 fixtures without introducing a fixture
format or production bypass.

The selected base checkpoint has 151,936 vocabulary entries, 1,024 residual
width, 28 layers, sixteen query heads, eight KV heads, head dimension 128,
query width 2,048, FFN width 3,072, context 40,960, and 310 tensors. Its
unchanged bytes remain terminally rejected as a product model. They may be
used only for conversion/runtime parity and as the ancestor of a newly trained
derivative.

## Output Boundary

The only output model profile is `org.minimodel.slm2/2.0` with weight profile
`tinyrustlm.weight-q8-row-symmetric-f32-scale/1`. Semantic role, not caller
choice or shape inference, selects storage:

- embeddings and attention/feed-forward matrices use row-wise signed Q8;
- final, layer, Q, and K normalization vectors remain F32;
- tied output weights are omitted;
- projection biases are forbidden for this Qwen3 family.

No dense-F32 model, alternate quantization, runtime repacking, dequantized
weight shadow, Qwen2 converter, alias, migration, compatibility reader,
fallback route, or temporary feature switch remains after the converter
replacement is complete.

Tokenizer2 and Template2 are not regenerated by model conversion. They already
have independent accepted byte authorities. ACG2 binds the exact model,
Tokenizer2, Template2, Sampling2, and Prompt2 members into one complete
composition.

## Durability

The converter writes a create-new staging file in the final directory,
synchronizes it, reparses and rehashes the complete SLM2 artifact, rechecks all
source identities, and promotes by a create-only same-directory operation. It
flushes the directory, writes the bounded receipt to separate staging, promotes
the receipt last, and flushes again.

An interrupted stage is retained as failure evidence. A promoted model without
its exact receipt is an incomplete preserved incident, never a successful
conversion. Existing output is never overwritten. There is no automatic retry
or cleanup that could erase the failure.

## Claim Boundary

A passing converter receipt proves exact source binding, deterministic format
conversion, complete SLM2 validation, output identity, and durability evidence.
It does not prove source-framework numerical parity, native runtime execution,
browser WASM behavior, assistant quality, P2P availability, release,
deployment, publication, or campaign progress.

The existing `Qwen/Qwen3-0.6B` base is specifically not promoted by this work.
The future derivative must independently pass untouched quality evaluation,
source/native/browser parity, real browser-local multi-turn conversation, and
release gates.

MemoryEndpoints remains unauthorized and disconnected. Campaign counters stay
at 0/20 qualified models, 0/50 deletion-backed browser rounds, 0/25 live memory
rounds, 0/40 outside-network lane proofs, and 0/20 live catalog announcements.

## Implementation Sequence

1. Commit and remote-verify this output-free preregistration.
2. Replace the Qwen2/F32 converter with one Qwen3 mixed-Q8 implementation.
3. Move converter execution identity into a neutral shared owner used by model
   and already accepted Tokenizer2 conversion.
4. Add deterministic BF16 and F32 tiny-Qwen3 conversion, exact repeat, hostile
   input, create-only, and receipt tests.
5. Run Rust formatting, locked tests, denied-warning Clippy, strict JSON,
   source scan, and secret/private-path scan.
6. Commit, push, fetch, and prove local, tracking, FETCH_HEAD, and actual remote
   equality before using the converter on large external bytes.
7. Convert the exact selected source only for numerical parity, while retaining
   its rejected product status.
8. Convert a genuinely qualified derivative only after its independent
   provenance, contamination, and untouched quality gates pass.

## Registration Status

This checkpoint creates no model bytes, receipt, runtime output, browser
output, quality result, or campaign credit. It changes no converter code. The
next executable change must match this profile exactly and delete the
superseded Qwen2 implementation in the same coherent converter replacement.
