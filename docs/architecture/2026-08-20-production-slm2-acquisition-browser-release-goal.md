## 7. Required Execution Order

### Gate A: Freeze Tokenizer2

Define one exact `tokenizer2.0` byte-level artifact profile for the selected
production family.

The contract must specify and test:

- Fixed magic, version, feature flags, section inventory, byte order,
  alignment, maximum sizes, and canonical ordering.
- Exact token IDs and token byte strings.
- Exact merge pairs and ranks for the selected BPE vocabulary.
- Added and special token identities, including beginning, end, padding, chat,
  tool, and generation-control tokens actually used by the selected family.
- Normalization, pretokenization, ByteLevel behavior, regex semantics,
  whitespace handling, invalid UTF-8 behavior, Unicode boundaries, and byte
  fallback behavior.
- Deterministic encode and decode behavior for ordinary, empty, multilingual,
  punctuation-heavy, whitespace-sensitive, malformed, and adversarial input.
- Duplicate token, duplicate merge, invalid rank, out-of-range ID, truncation,
  overlength, noncanonical ordering, unknown required flag, integer overflow,
  and allocation-preflight rejection.
- Exact linkage to the immutable upstream tokenizer source and conversion
  receipt without circular self-identification.

Use a bounded declarative parser. Do not embed executable publisher code or
reuse a general JavaScript tokenizer at runtime. Do not preserve an older
tokenizer format as a fallback.

Produce:

- A public profile document and machine-readable contract.
- A Rust writer, parser, encoder, and decoder.
- Independent language-neutral vectors generated without calling the Rust
  implementation under test.
- A second implementation or oracle in Node for differential replay.
- A hostile and truncation corpus.
- Exact source-to-artifact conversion receipts.

### Gate B: Freeze Template2

Define one exact, declarative, non-Turing-complete `template2.0` profile for the
selected publisher chat contract.

The contract must specify and test:

- Supported roles and legal ordering.
- System, user, assistant, and tool representation only when the selected
  family actually supports them.
- Exact inserted token IDs, separators, start/end markers, generation prompt,
  stop tokens, and empty-content behavior.
- Explicit thinking-mode behavior. Do not inherit an undocumented default.
- Message-count, content-size, nesting, total-token, and rendered-byte bounds.
- Rejection of executable expressions, loops, arbitrary field access,
  unknown operations, malformed roles, duplicate fields, and noncanonical
  encodings.
- Exact rendering parity with the pinned publisher template for all supported
  cases.
- Exact template artifact identity and relationship to tokenizer, model, and
  composition identities.

Produce a Rust renderer, an independent oracle, language-neutral vectors,
malformed cases, and source-template equivalence evidence. Do not evaluate
arbitrary Jinja or JavaScript in the browser or companion.
