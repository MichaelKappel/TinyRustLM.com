# Companion Source Operation Owner Profile Identity Correction Preregistration

## Decision

The output-free Companion source-operation registration committed at
`ac8b7a5ae728598b8d2bcb65d52969373f54cb28` bound the built-in Qwen3 source
descriptor to composition-profile SHA-256
`c30dcc162cb563f91bc3571fa165f910670f819c5134eed3ecf16a1d38ba85c0`.
That digest identifies the superseded composition `/3` profile. The sole
current converter authority is composition `/4`, whose exact 11,421 bytes have
SHA-256
`19e43c7ae532e7bc1822cbdcf179ee9bf1ed111298d3c6e5b13d37d990ee47e8`.

No source acquisition, operation root, converter launch, composition output,
browser execution, deployment, or campaign evidence occurred under the
incorrect registration. This correction therefore replaces the sole
prelaunch design before an implementation commit or real operation. It does
not repair, reinterpret, or promote evidence.

## Sole Authority

The Companion request, source descriptor, execution intent, acquisition
intent, conversion intent, Rust converter, managed verifier, fixture tool,
browser vectors, and documentation must accept and emit only composition
profile `tinyrustlm.qwen3-complete-composition-conversion/4` with SHA-256
`19e43c7ae532e7bc1822cbdcf179ee9bf1ed111298d3c6e5b13d37d990ee47e8`.

The `/3` digest is rejected. There is no dual reader, alias, migration,
translation, fallback, compatibility path, or legacy mode. The original
registration remains immutable source-control history and is marked
superseded-before-implementation-evidence by this correction.

## Ordering

This correction must be committed and pushed before the dirty implementation
work is committed. Any exploratory local build performed while discovering
the mismatch is not release evidence. Fresh implementation builds and tests
must bind the correction commit and the sole `/4` profile.

hashes, nine-file count, 1,519,207,688-byte aggregate source payload, source-only
