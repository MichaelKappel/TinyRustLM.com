# TinyRustLM Post-/10 Native Browser Release Intake Synthesis

Date: 2026-08-26

## Executive Decision

The twelve reports reinforce the existing first-model direction, but they do
not replace local source, frozen registrations, or observed execution evidence.
Proceed with one clean proof chain:

1. preserve `/10` as terminal failure;
2. register a wholly new output-free composition operation against remote-exact
   corrected source and wholly new private identities;
3. convert once and independently inspect the exact six-member composition;
4. compare a pinned source-framework oracle to a small scalar-native reference;
5. admit optimized native and browser-WASM kernels only through differential
   evidence against that chain;
6. close Tokenizer2, Template2, Sampling2, and Prompt2 semantics declaratively;
7. prove one exactly-once, cancellable, fresh-profile browser conversation;
8. make model selection perform an explicit qualified-P2P-or-local-conversion
   operation rather than downloading instruction files;
9. qualify behavior using untouched outputs, sealed cases, paired
   quantization comparisons, and human semantic review; and
10. release only from committed source with synchronized documentation,
    publication logs, deployment evidence, and HTTPS readback.

This intake authorizes no successor execution by itself. It proves only that
twelve advisory reports were preserved and reviewed. It does not qualify the
`/10` bytes, establish numerical parity, prove a useful model, prove browser
execution, establish direct P2P reachability, deploy a site, authorize
MemoryEndpoints, or advance any campaign counter.

## Consensus Incorporated Into The Plan

### 1. One Fail-Closed Cross-Language Contract

Rust, .NET, and JavaScript need one normative field and operation vocabulary,
one bounded parse profile, and one shared vector corpus. Syntax sharing must
not collapse independent semantic verification. The producer may state what
it attempted; the verifier must recompute file inventory, lengths, SHA-256,
member closure, path containment, and graph relationships from the candidate
and registration.

Operation status must describe one observation only. A field such as
`performed` cannot silently mean that a write was attempted, the operating
system returned success, the directory entry was synchronized, and an
independent verifier accepted the result. If stronger durability semantics are
needed, model them with distinct observations and platform-specific evidence,
not a renamed status accepted by only one language.

The immediate contract remains the corrected sole local contract. A generated
contract system is a separate design decision and is not a prerequisite merely
because a report selected one.

### 2. A Wholly New One-Shot Successor

The next execution requires a new output-free registration committed and
pushed before any private material. It must bind the then-current source commit
and tree, frozen goals, source locks, contract/profile identities, tool recipes,
exact command, resource bounds, and wholly new logical names for environment,
build custody, request, evidence, output, process, terminal, and verification
records.

Remote equality must include local `HEAD`, tracking, a fresh `FETCH_HEAD`, and
the direct remote ref. Every registered future root must be proven absent
without materializing it. The owner may launch once. Spawn ambiguity, timeout,
crash, inspector rejection, and owner defects all close that operation. No
candidate from `/10` may seed or satisfy the successor.

### 3. Independent Six-Member Semantic Inspection

Structural inspection should bind exactly:

- `model.slm2`;
- `tokenizer.tokenizer2`;
- `template.template2`;
- `sampling.sampling2`;
- `prompt.prompt2`; and
- `composition.acg2`.

The inspector should validate cheap fixed-size boundaries before allocating:
magic and schema identity, bounded counts, checked offsets, exact file length,
region non-overlap, alignment, dtype and quantization metadata, member names,
content hashes, source locks, and exact member-set closure. It should then use
the frozen Qwen3 architecture to derive expected tensor roles and shapes and
reject missing, duplicate, extra, overlapping, aliased, malformed, or
unsupported tensors.

A composition pass means the candidate is structurally and semantically
eligible for numerical work. It says nothing about correct logits, useful
conversation, browser feasibility, or release readiness.

### 4. Source Framework, Scalar Native, Optimized Native, Browser WASM

The numerical chain has four authorities with explicit arrows:

`pinned source framework -> converted scalar native -> optimized native -> real browser WASM`

The pinned source framework establishes publisher semantics. A deliberately
small scalar-native implementation becomes the reference for interpreting the
converted bytes, but it remains fallible and must be tested against source
observations. Optimized and WASM paths are differential implementations and
must never silently route to scalar after an unsupported operation or failed
kernel.

Capture comparisons at input text, rendered template bytes, token IDs,
positions, embeddings, selected layer boundaries, final hidden state, logits,
top-token ordering, sampled token, and KV append. Use first-divergence
localization rather than adjusting one final tolerance after failure.

### 5. Declarative Non-Weight Closure

Tokenizer2, Template2, Sampling2, and Prompt2 must carry all behavior needed to
reproduce the pinned publisher path without evaluating arbitrary Jinja,
Python, or artifact-supplied script in the runtime.

Tokenizer2 must preserve canonical token bytes, ID domains, merge ranks,
special tokens, encode/decode behavior, and hostile Unicode boundaries.
Trusted template-emitted special tokens must be distinct from identical text
inside user or retrieved content. Template2 should be a bounded role and turn
state machine. Sampling2 must specify every shipped default, RNG identity,
stable tie order, stop policy, and termination reason. Prompt2 should encode
authority and provenance categories without publishing private prompt text.

Cross-runtime vectors must cover JavaScript/.NET UTF-16 boundaries, unpaired
surrogates, NUL, combining marks, RTL controls, emoji sequences, special-token
injection, repeated token bytes, and incomplete UTF-8 decode state. Host API
replacement behavior must be specified and tested, never mistaken for the
original bytes.

### 6. Honest Browser Memory And Kernel Admission

The first real-browser proof should use a dedicated worker that owns model,
tokenizer, generation, and KV state. The design needs a measured peak-memory
and copy-count equation covering durable storage, reads, WASM linear memory,
model representation, scratch, activations, logits, tokenizer, context, KV,
JavaScript buffers, worker messages, and browser overhead.

OPFS synchronous access handles can support bounded worker reads, but reads
still move bytes into a destination buffer. File System Access, OPFS,
IndexedDB, direct-peer streams, and loopback streams should be compared with
actual copy and resident-memory telemetry. No storage API is inherently proof
that a roughly 598 MB candidate fits or runs interactively.

The initial kernel profile should favor deterministic semantics that can be
compared across native and browser targets. Relaxed SIMD is not the default
authority because its purpose permits implementation variation. Any future
relaxed profile needs its own preregistration, dispatch identity, measurements,
and noninferiority evidence; it cannot be a transparent compatibility path.

### 7. Exactly-Once Browser Conversation

Use linked state machines for installed composition, worker, conversation,
turn, generation, message, cancellation, and browser profile. Commands and
events should bind protocol, composition, conversation, turn, generation,
message, sequence, and bounded payload identities.

Exactly-once rendering means deduplicating events by identity and sequence,
not deduplicating token text. Repeated model tokens are legitimate. Late events
from a cancelled or replaced worker are never authoritative. Raw token IDs and
decoded output remain private and immutable; presentation may sanitize unsafe
markup but may not rewrite, complete, retry, or select a better answer.

Cancellation must stop work. If worker termination is required, discard that
worker and its KV state. A fresh worker must reopen and reverify immutable
installed bytes before another generation. A clean dogfood restart requires
actual browser process closure and deletion of an owned persistent profile;
reload, incognito, or clearing one storage API is insufficient.

### 8. Explicit P2P-Or-Convert Acquisition

Selecting a model must perform the requested operation. The route is:

1. resolve one exact qualified composition identity;
2. import those exact bytes from currently verified peers when available; or
3. explicitly acquire the pinned public source and convert locally when that
   exact peer composition is unavailable.

This is one deterministic route decision, not an invisible retry or fallback.
The UI must state the selected operation, source, storage requirement,
progress, cancellation state, and typed failure. Downloading a text, JSON, or
PowerShell handoff is not acquisition.

Piece mixing requires complete composition and piece-set identity agreement,
per-piece hashes, a bounded durable journal, quarantine on corruption, final
whole-member verification, and atomic activation. The browser-to-companion API
must be origin-bound, session-bound, least-privilege, and incapable of running
arbitrary commands, paths, or URLs.

### 9. No-Cheat Quality And Quantization Noninferiority

Screen the untouched pinned source before spending more conversion or training
compute. Evaluation must cover ordinary conversation, ambiguity, practical
constraints, conflicting authorities, latest-turn preference, multi-turn
references, untrusted quoted or retrieved instructions, factual uncertainty,
summaries, rewrites, JSON, extraction, code explanation, and substantive lawful
adult help with narrow harm boundaries.

Use fixed and seeded unseen paraphrase families, precommitted seeds, raw output
custody, deterministic invariants, non-authoritative model-judge signals, and
blinded human adjudication. Compare source and quantized paths on identical
rendered bytes, tokens, limits, seeds, sampling, and termination. Analyze
paired outcomes with family clustering and preregistered practical margins.
Catastrophic regressions need their own zero- or near-zero budget.

No failed holdout may become training data. No expected answer concepts may be
injected into runtime checks. No malformed output may be repaired. No lucky
seed may be selected. A candidate may honestly end in reject or research-only.

### 10. Enterprise Release And Living Documentation

Release evidence should form a content-addressed dependency graph from source
through conversion, semantic inspection, numerical parity, quality, browser,
acquisition, package/site release, deployment, and readback. A changed input
invalidates only dependent phases, while failed and superseded receipts remain
append-only history.

Every coherent green source change is committed and pushed before release.
Every affected site deploys only when its complete gate passes. Architecture,
format documentation, user instructions, privacy/security statements,
troubleshooting, marketing claims, publication log, visible technical release
identity, release date, and HTTPS readback must describe the same deployed
commit. Package creation, cross-compilation, or unit tests alone never mean
published or done.

## Corrections And Rejected Inferences

| Report assertion or pattern | Reviewed disposition |
| --- | --- |
| The Rust producer emitted an operation ID without `-members`. | False. Local registered source and `/10` evidence show Rust emitted `parent + "-members"`; the managed verifier was wrong. |
| The managed verifier correctly identified producer drift. | False as root-cause attribution. Its rejection made `/10` terminal, but the verifier expectation was the defect. |
| `/10` bytes are compromised and should be ignored. | Incorrect. They are unqualified and non-adoptable, but must remain preserved as immutable audit evidence. |
| AWS Smithy plus a proprietary compiler is mandatory. | Not adopted. It adds a generator and supply-chain surface. First evaluate a minimal checked descriptor or generated constants/vectors against the existing codebase. |
| A scalar-native implementation is an unimpeachable oracle. | Rejected. The pinned source framework is upstream semantic authority; scalar native is a small converted-byte reference that can also be wrong. |
| Qwen3-0.6B has 24 layers, 14 query heads, and 2 KV heads. | False for the pinned candidate. Local frozen authority is 28 layers, 16 query heads, and 8 KV heads. Several reports imported Qwen2.5-0.5B facts. |
| Vocabulary is either 151,669 or 151,936. | Both values have distinct domains: 151,936 model vocabulary capacity; 151,669 current tokenizer entries. Contracts must name the field and relationship. |
| The mixed-Q8 profile is GGML `Q8_0`. | Unproven and not adopted. The private SLM2 quantization contract controls; no external format may be inferred from approximate size. |
| OPFS or shared memory provides true or absolute zero-copy loading. | Rejected as a claim. Reads copy into a destination and browser implementations may add copies. Require measured copy accounting. |
| `crypto.subtle.digest` over independent chunks creates a streaming SHA-256. | False. Independent chunk digests do not equal one whole-file digest. Use a vetted incremental implementation or a bounded native/WASM streaming hasher. |
| A fixed 1.5 GiB allocation comfortably fits the model everywhere. | Unsupported. Peak memory must be derived from the actual artifact/profile and probed on each browser build and device class. |
| Memory64 imposes a universal 10 percent cost. | Unsupported generalization. Treat address model and performance as target-specific measured facts. |
| Relaxed SIMD should be mandatory with transparent scalar/SIMD fallback. | Rejected. Relaxed SIMD conflicts with strict parity, and transparent fallback violates the product boundary. Admit one explicit proven profile at a time. |
| Firefox/WebKit support is proven from public documentation. | False. Only local real-browser execution can prove this product and artifact. |
| Conversion is the fallback after P2P. | Corrected terminology: P2P-or-convert is one explicit deterministic decision; neither branch is hidden. |
| Fixed quality ratios, tolerances, memory ceilings, or speedups can be copied from a report. | Rejected. Thresholds require preregistration from local baselines, risk budgets, and sealed cases. |
| Adopting in-toto, SLSA, CycloneDX, or Sigstore wording establishes a supply-chain level. | Rejected as a claim. Standards can inform schemas, but conformance and level claims require exact implementation and evidence. |

## Decisions By Status

### Adopt Now

- preserve the raw report bytes and route through this corrected synthesis;
- retain one fail-closed contract and the exact `/10` negative fixtures;
- create only a wholly new output-free successor registration;
- use the frozen Qwen3 architecture as the semantic inspection oracle;
- require source-to-scalar-to-native-to-browser differential evidence;
- keep non-weight semantics declarative and composition-bound;
- use one worker-owned generation path with exactly-once rendering;
- use explicit qualified-P2P-or-local-conversion acquisition;
- keep quality evaluation sealed, paired, raw, and human-audited; and
- synchronize code, documentation, claims, publication logs, and deployment.

### Evaluate Through TDD Before Adoption

- a generated cross-language contract descriptor;
- RFC 8785 or another canonical encoding for new receipt families;
- per-file versus directory-level durability observations;
- the exact SLM2 tensor/quantization semantic inspector surface;
- `f32` versus widened diagnostic accumulation boundaries;
- incremental private tensor observation and Merkle summaries;
- OPFS versus companion-owned artifact storage;
- deterministic SIMD profile and browser memory admission limits;
- exact quality sample sizes and noninferiority margins; and
- specific supply-chain attestation formats.

### Do Not Adopt

- report-derived Qwen2.5 architecture values;
- `/10` reinterpretation, repair, adoption, or rerun;
- dual contract readers or permissive status acceptance;
- an unreviewed Smithy/proprietary-compiler dependency;
- BLAKE3 substitution for existing SHA-256 identities without a clean-slate
  contract decision;
- arbitrary Jinja or publisher scripting in the runtime;
- fixed browser support, memory, or performance claims without probes;
- transparent kernel, inference, network, or acquisition fallback;
- opaque-judge-only evaluation or best-of-N; or
- any MemoryEndpoints or campaign credit.

## Prioritized Implementation Route

1. Commit, push, fresh-fetch, and four-way verify this report-intake checkpoint.
2. Create a new output-free successor registration that binds that exact
   source commit/tree and wholly new absent private names.
3. Execute its owner once and preserve its terminal result without retry.
4. On pass only, implement or run independent six-member semantic inspection.
5. Build source-framework and scalar-native differential vectors for the exact
   candidate, then localize first divergence.
6. Admit optimized native kernels through the scalar gate with no fallback.
7. Close Tokenizer2, Template2, Sampling2, and Prompt2 cross-runtime vectors.
8. Implement the bounded worker WASM path and prove it in real Chromium with
   measured memory, copies, cancellation, restart, and network privacy.
9. Complete one multi-turn clean-profile conversation with exactly one render
   per answer and preserve raw private output.
10. Replace instruction-file model selection with explicit P2P-or-convert
    acquisition and atomic activation.
11. Run source-first quality screening and paired quantization noninferiority;
    reject honestly if the model is not useful.
12. Package, document, log, deploy, and HTTPS-readback only the evidence-backed
    slice.

Each phase consumes immutable identities from its prerequisites. A contract,
source, tokenizer, template, prompt, sampling, quantization, runtime, evaluator,
browser, or deployment change invalidates every dependent receipt, never the
independent history that preceded it.

## Open Local And Authorized Facts

- Whether its six members match the frozen architecture and private formats.
- Exact quantization packing, scale, tail, and accumulator semantics.
- Source-framework versus converted scalar logits and first divergence.
- Optimized native behavior on win-x64, linux-x64, and linux-arm64 hardware.
- Real browser memory, copy count, throughput, cancellation, and recovery.
- Whether Qwen3-0.6B passes practical source-first conversation screening.
- Quantized behavioral noninferiority and catastrophic regression rates.
- Qualified direct-peer reachability and companion deployment behavior.
- Signing, package publication, hosting credentials, and public HTTPS readback.

Until those facts exist, claims and campaign counters remain unchanged.
