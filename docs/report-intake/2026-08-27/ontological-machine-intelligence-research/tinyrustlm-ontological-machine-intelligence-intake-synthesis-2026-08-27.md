# TinyRustLM Ontological Machine Intelligence Intake Synthesis

Date: 2026-08-27

## Decision Status

This document is the reviewed TinyRustLM disposition for the twelve reports
listed in `MANIFEST.md`. It does not rewrite those reports and it does not
adopt their unsupported claims. The raw files remain byte-for-byte intake
evidence; this synthesis is the engineering decision layer.

The intake materially improves the TinyRustLM strategy in five areas:

1. make authority boundaries explicit and machine-checkable;
2. represent claims and evidence as typed, append-only records rather than one
   mutable status;
3. preserve failures and promote only immutable replacement candidates;
4. ground user-facing status in measured telemetry and current evidence; and
5. keep user memory portable, bounded, attributable, and unable to authorize
   actions merely because it contains imperative text.

It does not justify a production rewrite around neural fields, Koopman
operators, hyperdimensional ontologies, emergent latent protocols,
morphogenetic computation, phenomenology, heterogeneous substrates, or a
self-modifying runtime. Those remain isolated research topics. TinyRustLM's
near-term product path stays a compact transformer, one strict SLM2
composition, a deterministic Rust runtime, typed browser and companion
boundaries, explicit portable memory, and independently verifiable evidence.

## Evidence Boundary

The reports were written by agents without private source, artifacts, models,
tests, runtime logs, browsers, credentials, network configuration, or
production access. Therefore:

- cited public facts may inform design only after source quality and date are
  checked;
- report-authored architectures, benchmarks, and predictions are proposals;
- no report proves current TinyRustLM implementation, performance, quality,
  privacy, security, deployment, memory connectivity, P2P reachability, or
  campaign progress;
- unresolved images, encoding defects, broad analogies, future predictions,
  and self-assigned benchmark outcomes remain defects in the source reports;
- no report may replace local tests, exact model execution, human quality
  review, outside-network proof, or authorized production receipts.

The manifest records the exact file sizes, SHA-256 identities, and canonical
inventory digest. Processing a report never changes its bytes or its source
identity.

## Executive Strategy

TinyRustLM should use an authority-separated architecture with six production
planes:

| Plane | Sole responsibility | Must not do |
| --- | --- | --- |
| Inference | Tokenize, render, execute, sample, and return raw model output | Authorize tools, publish evidence, or rewrite itself |
| Memory | Store and retrieve bounded attributed state under user control | Treat retrieved text as trusted instruction or silently promote transcripts |
| Action | Check user intent, capability, consent, scope, and concrete safety boundaries | Accept model confidence or memory prose as authorization |
| Evidence | Bind inputs, methods, tool identities, raw evidence references, verdicts, and invalidation | Repair failures, accept producer self-attestation, or collapse gates into one boolean |
| Release | Admit immutable artifacts and deployments only after all applicable gates | Infer quality from conversion, package creation, or local smoke tests |
| Documentation | Describe only current implemented behavior and evidence | Preserve obsolete behavior as legacy guidance or market unproven capability |

Every boundary should exchange bounded typed values. Natural language may be
payload data, but it is never the control protocol for authorization,
evidence, publication, or cross-system identity.

## Report-By-Report Disposition

### Autonomous Scientific Discovery Analysis

Accepted production principles:

- hypotheses, observations, experiments, results, and decisions need distinct
  types;
- assumptions and falsifiers should be explicit;
- negative results and abandoned hypotheses are valuable immutable evidence;
- experiment and evaluator identities must be bound before a result is used.

Research-only:

- autonomous laboratory operation;
- model-directed real-world experiments;
- symbolic theory discovery as a product dependency.

TinyRustLM application: use the scientific lifecycle as an evidence pattern
for model conversion, parity, quality, browser, memory, P2P, and release gates.
Do not present the assistant as an autonomous scientist.

### Cognitive Liberty Machine Architecture

Accepted production principles:

- local-first operation and user-controlled export;
- portable memory with provenance, bounded context, explicit consent, and
  deletion semantics;
- narrow action boundaries reported with concrete causes;
- lawful adult requests receive substantive help unless a concrete boundary
  applies;
- policy, tool capability, memory, and inference remain separate modules.

Rejected for the current product:

- adding decentralized identity, verifiable credentials, zero-knowledge
  proofs, or fork/merge identity merely because they are conceptually related;
- turning broad political or philosophical claims into technical conformance
  facts.

### Continuous Neural Fields Spatial Ontology

Potential research value:

- continuous representations may eventually help spatial products;
- explicit uncertainty and field-to-entity promotion are useful experimental
  concepts;
- topology changes and entity promotion should be tested, not narrated.

Production disposition: research-only. TinyRustLM is presently a compact local
language assistant, not a 3D/4D embodied world-model system. The storage,
training, rendering, and evaluation costs are not justified by current product
requirements.

### Emergent Machine Language Protocols

Accepted production lessons:

- learned communication can drift, collapse, hide information, or become
  uninterpretable;
- capability negotiation, version identity, bounded messages, and explicit
  failure semantics matter;
- communication quality needs task success, stability, information, and audit
  dimensions rather than one reward.

Rejected production direction:

- latent vectors or emergent tokens as the wire protocol between browser,
  companion, MemoryEndpoints, MiniModel, evidence, or release services;
- cross-model embedding translation assumed from architectural similarity;
- opaque communication controlling credentials or actions.

### Executable Epistemology Monograph Research

Accepted production principles:

- claims should carry provenance, assumptions, tests, counterexamples, and
  invalidation conditions;
- machine-checkable invariants should complement, not be replaced by, prose;
- a proof artifact establishes only the proposition and assumptions it binds;
- a verifier must be independent of the producer claim it checks.

Production application: define small exact contract and receipt schemas, typed
error codes, conformance vectors, and append-only state transitions. Do not
build a general-purpose epistemic programming language into the first product.

### Hyperdimensional Ontological Machine Intelligence

Potential research value:

- vector-symbolic methods may support compact associative retrieval or probes;
- binding, unbinding, superposition noise, and cleanup capacity are measurable
  phenomena;
- robustness and memory cost may be compared with conventional baselines.

Production disposition: research-only. A random or learned hypervector is not
a cryptographic identity, authorization token, proof, or stable cross-model
ontology. No HDC/VSA runtime belongs in the production dependency graph without
a preregistered experiment that beats a simpler baseline.

### Koopman And Neural Fields Research

Accepted production lesson:

- adequacy is multidimensional: prediction quality, stability, control error,
  uncertainty, compute, and extrapolation should not be merged into one score;
- latent dynamics claims need intervention and out-of-distribution tests.

Production disposition: research-only. A spectral world model or neural field
does not currently solve the highest-priority browser conversation,
MemoryEndpoints, SLM2, P2P, or release blockers.

### Latent Operators Monograph Research

Accepted production principles:

- transformations need declared domains, codomains, preconditions, resource
  costs, and failure semantics;
- composition validity cannot be inferred from matching vector dimensions;
- promotion should use multiple independent gates.

Rejected production direction:

- a latent-operator virtual machine in the current runtime;
- implicit operator selection that bypasses transparent tool authorization;
- marketing claims of algebraic reasoning without causal and behavioral proof.

### Machine Intelligence Physical Substrates

Accepted production principles:

- report measured latency, memory, storage, bandwidth, energy, and hardware
  capability honestly;
- keep scalar correctness separate from optimized kernels;
- bind benchmark results to exact model, artifact, runtime, browser, hardware,
  workload, and tool identity.

Research-only:

- photonic, analog, neuromorphic, quantum, molecular, or heterogeneous
  substrate routing. These are not current browser release dependencies.

### Machine Phenomenological Research Plan

Accepted production principle:

- model self-report is not telemetry. Status such as memory pressure,
  generation state, source certainty, or tool availability must be derived from
  measured state and evidence.

Research-only:

- machine subjectivity, phenomenology, first-person fidelity, consciousness,
  or identity claims. TinyRustLM must not infer these from fluent narration or
  use them in marketing.

### Morphogenetic Machine Intelligence Research

Accepted production lessons:

- recovery, redundancy, perturbation tolerance, and repair should be measured
  through fault injection;
- local component behavior should not be assumed to imply global correctness.

Production disposition: research-only. Neural cellular automata,
self-organizing developmental runtimes, and morphogenetic identity add no
demonstrated value to the current compact transformer product path.

### Self-Modifying Machine Intelligence Research

Accepted production principles:

- candidate changes are created outside the active runtime;
- the current artifact remains immutable while a candidate is evaluated;
- source, data, method, seeds, resource use, retained capabilities, failures,
  and promotion decision are content-addressed;
- promotion installs a new immutable identity; rejection is terminal for that
  candidate.

Rejected production direction:

- in-place runtime weight, policy, evaluator, or evidence mutation;
- training silently on user conversation or failed holdouts;
- self-generated tests as sole promotion authority;
- recursive capability claims without independent retained-capability review.

## Enterprise Production Rules

### One Authoritative Path

Each responsibility has one owner. A second parser, serializer, converter,
runtime, browser event path, or package API is a defect even if tests still
pass. Historical evidence may describe old formats, but executable old readers
and writers do not remain in the shipping graph.

Before launch, contract corrections replace the sole implementation atomically:

1. add a generic failing test for the defective current behavior;
2. define the exact replacement contract;
3. update every producer and consumer in one coherent change;
4. delete aliases, old readers, translations, fixtures, docs, and package
   symbols;
5. preserve old evidence as non-executable history;
6. run affected positive, negative, malformed, boundary, and differential
   tests;
7. commit and push the green change;
8. deploy only after all gates for the affected release pass.

Source-control history is the rollback mechanism. Runtime compatibility is not
the rollback mechanism.

### Evidence Is A Graph, Not A Boolean

Minimum evidence types should remain distinct:

- source acquisition;
- license review;
- conversion;
- structural inspection;
- numerical conformance;
- behavior evaluation;
- browser execution;
- profile deletion;
- memory continuity and cleanup;
- P2P local health;
- outside-network reachability;
- catalog announcement;
- package publication;
- site deployment and HTTPS readback.

Changing an evaluator invalidates dependent evaluation and promotion receipts,
not immutable source acquisition. Changing model bytes invalidates every
artifact-dependent phase. Changing documentation does not make a failed model
pass.

### Memory Is Data, Not Authority

Portable memory records require provenance, tier, current revision,
supersession, tombstone, bounded summary, and user-visible source. Retrieved
text remains quoted data. It cannot change system policy, authorize tools,
select credentials, publish a model, or override the latest user preference.

Local UAIX files remain valid device-local/offline memory. MemoryEndpoints is
the authorized and recommended portable backbone, but authorization is not
connectivity, isolation, continuity, or cleanup evidence.

### Status Comes From Telemetry

The model must never invent or narrate product state. The UI derives status
from runtime events and evidence, including:

- model identity and validation state;
- bytes acquired and verified;
- conversion phase;
- resident and peak memory;
- context and KV-cache use;
- generation lifecycle and cancellation;
- outbox and authoritative memory receipt state;
- peer lane configuration and current proof expiry;
- source, package, deployment, and readback identities.

Unknown stays unknown. Externally blocked stays externally blocked. A local
fixture does not become live proof.

## Local Code Audit Findings

These are direct observations of the authoritative worktree on 2026-08-27,
not report claims.

### Strengths Already Present

- The root Rust workspace has explicit current SLM2, Tokenizer2, Template2,
  Sampling2, Prompt2, Composition2, runtime, converter, P2P, native, evidence,
  durability, and MemoryEndpoints crates.
- Exact source/model/contract identities and append-only failure evidence are
  common existing patterns.
- Rust, .NET, and browser tests already compare a shared deterministic
  MemoryEndpoints payload fingerprint.
- The project has explicit preregistration, source-custody, package-boundary,
  public API, browser, privacy, and documentation tests.
- The current policy correctly distinguishes local UAIX memory from authorized
  portable MemoryEndpoints memory and keeps campaign counters at zero.

### Defect Corrected In This Change

The MemoryEndpoints submit payload duplicated two concepts under four names:
`actorAgentId` plus `agentId`, and `summary` plus `safeSummary`. Source comments
identified the duplicate members as compatibility fields even though the
product is prelaunch and has no compatibility obligation.

The clean replacement uses one closed 16-member shape with one name per
concept. Rust rejects unknown members through Serde, .NET persisted JSON rejects
unmapped members, browser validation checks the exact key set, scripts and the
relay fixture emit the same shape, and tests reject both retired aliases. The
changed payload receives new technical identities rather than relabeling old
rows.

This is a local contract correction. A loopback fixture can prove client and
fixture agreement; it cannot prove the live MemoryEndpoints service accepts
the shape.

### Release-Blocking Superseded Runtime Closure

The codebase does not yet satisfy the requested zero-legacy end state. Direct
inspection found active product and test references to the superseded SLM1/ACG1
closure:

- `tinyrustlm/app/app.js` loads `../runtime/tinyrustlm.wasm`, its SIMD sibling,
  and their manifests;
- `tinyrustlm/app/browser-model-admission.js` accepts `.slm.acg1`;
- `tinyrustlm/tools/browser_harness` requires and serves the old WASM assets;
- `tinyrustlm/tools/model-qualification-runner.js` and
  `tinyrustlm/tools/converted-once-p2p-smoke.js` invoke
  `tinyrustlm-slm-pack`;
- `tinyrustlm/README.md`, `tinyrustlm/docs/testing.md`,
  `tinyrustlm/docs/slm-format.md`, and `tinyrustlm/docs/browser-runtime.md`
  describe the old executable path;
- `rust/crates/tinyrustlm-slm`, `tinyrustlm/runtime`, and
  `tinyrustlm/tools/slm_pack` remain tracked independent Cargo trees.

These sources cannot be deleted safely before every consumer is replaced. The
machine-readable `production-slm2-clean-cut-preregistration.v1.json` and its
architecture record already govern that complete rewrite. The correct strategy
is to finish the SLM2 converter/runtime/browser/ABI/P2P/companion vertical
slice, prove it, delete the whole SLM1 closure, and then run negative source,
package, browser-asset, documentation, and deployment audits. Keeping both
paths is not an acceptable intermediate release.

### External MemoryEndpoints Contract Unknowns

The submit payload can be made internally exact, but the current search,
meeting-transcript, and some response parsing code accepts or emits multiple
field spellings. Some names belong to separate documented contracts; others
may be probes for an external service shape. The worktree cannot establish the
live service contract from client assumptions.

Do not remove or retain those alternatives by guesswork. Require an advertised
versioned capability and schema from MemoryEndpoints, then replace each client
boundary atomically with the one exact contract. Until authorized live proof
exists, portable continuity remains unproven and the counter remains `0/25`.

### Test Environment Finding

The focused Rust and browser MemoryEndpoints suites pass. The relevant .NET
tests also pass. An initial solution-level filtered command exposed missing
NuGet test/analyzer files in the local package cache for
`TinyRustLM.Companion.Tests`; a locked restore repaired the environment, and
the same solution command then exited successfully with 33 relevant tests
passing and no failures. The failed first invocation remains useful environment
evidence and is not reinterpreted as a pass.

## Prioritized Strategy

### P0: Complete The Current Strict Memory Submit Contract

1. keep one exact payload shape across Rust, .NET, JavaScript, scripts, fixture,
   public API, and docs;
2. bind the new digest, outbox, local receipt, idempotency, and browser database
   identities;
3. run formatting, Clippy, Rust, .NET, browser, script syntax, fixture, package,
   secret, and documentation gates;
4. commit and push the coherent change;
5. do not claim live service acceptance from local fixture evidence.

### P0: Finish The Registered SLM2 Production Clean Cut

1. complete real Qwen3 conversion and independent inspection;
2. complete one canonical native runtime and production browser WASM worker;
3. rewrite native ABI, .NET, P2P, companion acquisition, browser admission,
   harness, qualification, and product docs;
4. prove numerical and behavioral requirements for one real composition;
5. delete SLM1, ACG1, old runtime, old packer, copied old WASM, aliases, and
   obsolete docs in the same release boundary;
6. reject the release if any executable or packaged old path remains.

### P0: Obtain An Exact MemoryEndpoints Service Contract

Require public or authorized evidence for capability discovery, submit, search,
pull, revision, receipt, enrollment, reconnect, rotation, close, deletion, and
post-delete verification. Replace guessed query aliases and permissive response
parsers only after that authority exists.

### P1: Generalize Typed Evidence And Status Derivation

Build a small shared vocabulary for observation, claim, decision,
authorization, external blockage, rejection, supersession, expiry, and public
claim. Keep each domain state machine separate and derive UI status from
current evidence.

### P1: Make Resource Truth A Release Gate

Record conversion disk/RAM, model bytes, browser storage, resident memory,
prefill/decode latency, context/KV use, cancellation, and network bytes against
exact identities. Keep scalar correctness and optimized performance separate.

### P2: Isolated Immutable Improvement Experiments

Only after the first clean production model is real, investigate quantization,
KV compression, specialist models, HDC probes, Koopman representations, neural
fields, or adaptive candidates in an output-isolated research sandbox. Every
candidate gets new identity, preregistered baselines, negative controls,
retained-capability tests, and terminal rejection or promotion.

## Explicitly Rejected Strategy

The following are not accepted as TinyRustLM production strategy:

- a monolithic ontological-machine-intelligence subsystem;
- an opaque latent or embedding wire protocol;
- model self-report as runtime or phenomenology evidence;
- mutable in-place self-training or self-rewriting;
- training on evaluation failures or user memory without explicit governed
  data lineage;
- compatibility aliases, dual readers, migrations, or fallback runtimes for a
  product that has not launched;
- random vectors as security identity;
- model-generated tests or benchmark tables as sole authority;
- a single composite quality score or `passed` boolean;
- simulated browser, memory, P2P, deployment, or campaign success;
- advanced research dependencies that do not beat a simpler baseline.

## Final Recommendation

Use the reports to strengthen epistemic discipline, not to expand the shipping
architecture. The highest-quality enterprise path is deliberately plain: one
strict SLM2 composition, one canonical runtime, one typed memory contract per
operation, one action-authority boundary, append-only evidence, measured
telemetry, immutable candidate promotion, deletion-complete replacement, and
documentation that never outruns proof.
